### flower

#### 一、思路

DIE查壳 32 位 PE 校验程序，程序接收用户输入
经过复杂加密校验后判断输入是否为正确 Flag
程序存在大量花指令干扰，导致 IDA 静态分析报错、函数截断、无法直接 F5 反编译
`call $+5 / add [esp],8 / retn` 花指令破坏 IDA 栈平衡分析，产生 sp-analysis failed

---

#### 二、分析

##### 2.1 花指令

程序中大量重复出现固定三段式垃圾指令

```asm
call $+5
add dword ptr [esp], 8
retn
```

执行逻辑：call 压入返回地址  add 修正栈  retn 跳转

| 影响 | 结果 |
|---|---|
| 对程序运行 | 无影响 |
| 对 IDA 分析 | 破坏栈帧分析，函数提前截断，无法反编译 |

##### 2.2 NOP填充

消除 IDA 分析错误，将所有成套花指令完整替换为 NOP

`call $+5` 5 字节  5 个 NOP
`add [esp],8` 4 字节 4 个 NOP
`retn` 1 字节  1 个 NOP

覆盖所有执行路径上的干扰花指令

##### 2.3 核心逻辑

清理花指令后梳理核心校验逻辑

程序限制输入长度为 29 字节  0x1D
循环 29 次逐字符校验
最终所有轮次的 cl 必须等于 0，否则校验失败

核心运算汇编

```asm
lea eax, [ebx*8]
sub eax, ebx
add eax, 3
div ecx        ; ecx = 25
; eax = (7*ebx+3)/25, edx = (7*ebx+3)%25

movzx eax, byte_4021A0[ebx]
mov cl, byte_402180[edx]
xor cl, input[eax]
xor cl, byte_4021C0[ebx]
or  [ebp-1], cl
```

##### 2.4 加密算法

最终校验条件：所有轮次 `cl` 必须等于 0，否则校验失败

```
byte_402180[edx] ^ input[pos] ^ byte_4021C0[ebx] = 0
```

变形得到明文公式

```
input[pos] = byte_402180[edx] ^ byte_4021C0[ebx]
```

| 变量 | 含义 |
|---|---|
| `edx` | `(7 * ebx + 3) % 25` |
| `pos` | `byte_4021A0[ebx]`，字符在 flag 中的位置 |
| `ebx` | 遍历 0 ~ 28，共 29 轮 |

---

#### 三、数据提取

三个关键数组储存在 `.rdata` 数据段,不受影响

| 数组 | 长度 | 说明 |
|---|---|---|
| `byte_402180` | 25 字节 | 查表用，按 edx 索引 |
| `byte_4021A0` | 29 字节 | 位置置换表，决定字符顺序 |
| `byte_4021C0` | 29 字节 | 每轮的异或值 |

#### 四、解密

```python
arr1 = [44, 177, 250, 64, 46, 209, 223, 59, 55, 31, 67, 86, 72, 173, 218, 231, 123, 74, 51, 62, 48, 18, 152, 212, 156]
arr2 = [12, 3, 28, 0, 18, 8, 5, 15, 1, 23, 10, 6, 20, 4, 16, 2, 27, 9, 13, 21, 7, 17, 14, 24, 11, 19, 22, 26, 25]
arr3 = [31, 23, 55, 219, 156, 224, 99, 148, 74, 74, 186, 225, 44, 69, 218, 114, 147, 216, 100, 101, 108, 115, 78, 180, 107, 112, 28, 35, 195]

flag = [0] * 29
for ebx in range(29):
    edx = (7 * ebx + 3) % 25
    pos = arr2[ebx]
    flag[pos] = arr1[edx] ^ arr3[ebx]

print(bytes(flag).decode())
```
